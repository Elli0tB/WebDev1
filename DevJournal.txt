    concepts for the backend: 
        Interface: where a user can interact with the machine in a visual way, but it can be text with command line. 
        Interface's allow for a common way for people, or other machines to connect, like pluging into a wall socket. 
        we need to be carful about how we make the api interface, large changes that destory will break downstream users code. 
        however makeing small changes that add without breaking will allow old downstream users and new stream users work together

        3-Tier Architecture: 
            this is a Frontend -> Backend -> Database 
            for this we need interface's that should be clean and modular not hard coded that will make it increadably difficult to change, 
            or even have others connect through the same inerface. 

        API Keys: 
            never put this on git or on the front end. It should always be in the backend and it should be saved to the machine not git
            
        HTTP methods: 
            GET: gets stuff, Idempotent
            POST: sends stuff, not Idempotent makes a new object each time
            DELETE: deletes stuff 
            PUT: sends stuff, Idempotent wont make a new object each time it will replace whatever was in that spot 
            HEAD: says what could happen 
            OPTIONS: same as head 
            PATCH: updates to have the new thing you add
